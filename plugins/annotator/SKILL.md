# 页面标注工具（annotator）

在**真实运行的应用界面**上点选元素或框选区域写批注，导出一份**可执行**的修改说明。

## 何时使用

- 用户说「这个按钮太小」「这块留白太多」「我想让卡片标题更醒目」这类界面意见
- 需要精确指明是哪个元素（而不是靠文字描述位置）
- 反馈需要留档，供后续对照「改前 / 改后」

## 为什么不是截图圈一下就行

批注里写「这个按钮太小」是无法执行的。而执行改动的一方**未必看得到截图**
（比如由模型来改代码）。所以工具会自动采集：

- `data-component` 组件名与父级链 → 直接定位到源码文件
- 唯一 CSS 选择器
- 元素可见文本
- 关键计算样式（字号 / 颜色 / 内边距 / 圆角 / 阴影 / transition…，已过滤掉无信息量的默认值）
- **WCAG 对比度**（文本色与背景色都不透明时）→「好看」里最硬的一条指标
- 标注框的坐标与尺寸

## 操作步骤

### 用户侧（在应用里）

1. 按 `Ctrl+Shift+A`，或点顶栏右侧的笔形按钮
2. 默认在**浏览**模式，不拦截任何点击 —— 正常操作应用，翻到要提意见的那一屏
3. 切**点选**：悬停实时高亮元素并显示所属组件，点一下即可写批注
4. 或切**框选**：按住左键拖出矩形，给一整片区域提意见
5. 每条批注可标**类别**（视觉样式 / 布局结构 / 文案内容 / 交互行为 / 缺陷 / 其它）
   与**优先级**（必须改 / 建议改 / 锦上添花）
6. 右下角「标注清单」可回看、跳转、编辑、删除
7. 点「导出标注」→ 填一句总体说明 → 确认

导出只写 `devlog/` 下的文件，**不改任何代码**，可以放心多点几下。

### 执行侧（拿到批注之后）

```bash
npm run round -- inbox     # 打印最新一轮的标注原文
```

读 `annotations.md` 里的组件名定位源码，按「当前样式」对照着改。

## 产物

导出到 `devlog/rounds/<轮次>/`：

| 文件 | 内容 |
| --- | --- |
| `annotations.md` | 人读版：每条批注 + 全部采集信息 |
| `annotations.json` | 机读版：原始数据 |
| `screenshots/00-full.png` | 导出时的整页截图 |
| `screenshots/NNN-*.png` | 每条标注自动裁切的局部截图 |
| `README.md` | 轮次说明骨架 |

## 自检

```bash
npm run annotatecheck
```

程序化驱动真实界面走完「打开 → 点选 → 写批注 → 框选 → 导出 → 校验落盘产物」，18 项断言。
使用临时工作区（`GUGU_WORKSPACE`），不会污染真实档案。

## 常见问题

- **按了没反应**：确认 devlog 插件也在 `plugins/plugins.json` 里 —— annotator 依赖它
- **导出报「插件未加载」**：同上；或检查构建时 `GUGU_PLUGINS` 是否把插件排除了
- **截图裁切位置偏了**：多为 devicePixelRatio 取值问题，检查导出时的窗口缩放
