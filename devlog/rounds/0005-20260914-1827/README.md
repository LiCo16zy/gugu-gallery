## 改动

### 一、四个关键缺陷（都有明确根因）

**1. 标注工具栏右半边点不动**（用户当面反馈）

现象很怪：工具栏左边几个按钮能点，右边的完全没反应。

根因：上一轮为了自绘标题栏，把整条顶栏设成了 `-webkit-app-region: drag`（窗口拖动区）。
Chromium 只会把**后代元素**里标了 `no-drag` 的部分从拖动区里挖出来 ——
搜索框正好是 no-drag 且横跨工具栏左半边，于是左边能点、右边落进拖动区被窗口吞掉。
用户描述的「中间向左能点、向右不能点」和这个分界线完全吻合。

修法：不赌实现细节，直接把工具栏放到顶栏下方（`top: 66px`）彻底避开拖动区，
并顺手补上 `no-drag`。回归断言：工具栏整体必须位于拖动区下方。

**2. 界面能左右滚动**（用户当面反馈）

根因：瀑布流的列宽是拿 `grid.clientWidth` 算的，而这个值**包含左右内边距**，
于是列宽总和比内容盒宽出 `2 × 18px`。实测横向溢出 18px。

修法：先减掉 padding 再算，并给 `.main` 明确 `overflow-x: hidden`。

**3. 灯箱竖图仍然溢出屏幕 + 滚轮完全无效**（标注 14）

两个独立的问题：

- **滚轮**：上一轮把监听器从 React 合成事件换成原生 `addEventListener` 时，
  漏了给舞台元素加 `ref` —— 监听器从头到尾就没挂上过。
- **溢出**：上一轮的修法（`grid-template-rows: minmax(0,1fr)`）方向对了但不够。
  实测六种写法，只有**绝对定位**那两种能让百分比高度真正生效：
  居中网格项里的 `max-height: 100%` 解析不了，竖图一路撑到 1713px。
  最终改成 `position:absolute; inset:0; margin:auto` +
  `max-width/max-height: calc(100% - 2×内边距)`，
  竖图现在 376×668、四周留白 24px，横图也正常。

**4. 侧栏收不起来**（标注 9）

根因：收起时靠 `.sidebar-collapsed` 把 `--sidebar-w` 改成 64px，
但根节点上写了**内联**的 `--sidebar-w`，内联优先级更高，把类里的值盖掉了。
修法：收起时内联值也写 64px。

### 二、筛选逻辑重整（标注 23 + 「筛选逻辑存在问题，自行重整」）

查下去发现是个**真 bug**，不是逻辑别扭：

`listItems` 的计数查询漏了 `LEFT JOIN files`，但 `where` 在「已下载 / 待下载」
时会引用 `f.id` —— 一按筛选就抛 `no such column: f.id`，整个查询失败，
列表于是停留在旧数据上，看起来就像「筛选没生效」。

修完 JOIN 之后，又把互斥规则补成**双向**的：

- 「待下载」与其它所有筛选项互斥（选中它会清掉别的，选中别的也会把它清掉）
- 「已下载」只与「待下载」互斥，可以叠加收藏、横竖图、标签

上一轮只做了单向，会出现「点 A 清了 B，再点 B 却清不掉 A」的自相矛盾状态。
另外「全部」的高亮判定补上了构图与尺寸条件。

## 遗留

- 沉浸模式目前只记住「开/关」，没有记住右栏宽度
- 下载进度条显示的是**整批任务**的进度，不是单张图片的进度 ——
  抓取引擎是按队列推进的，要精确到单张需要给引擎加按条目的事件
- 回到顶部的触发阈值（320px）是拍脑袋定的，实际手感可能还要调
- 标注工具本身只加了「工具栏在拖动区下方」这一条断言，
  真实鼠标点击（`sendInputEvent`）仍未纳入自动化，这类问题只能靠几何断言兜住
