## 改动

### 1. 帮助里那颗按钮：三击才进入退出确认

状态机（本地、跟着帮助面板的生命周期走）：

```
未登录 / 凭据失效      → 「登录」/「登录已失效」，点击打开登录引导
已登录                 → 「已登录」（灰），点击不跳转，文字抖动一下
                        → 第 3 次点击平滑变红并切成「退出登录?」
「退出登录?」          → 点击执行退出：清掉加密凭据、通知侧栏、清掉「来源分类」筛选
退出之后               → 「已退出」（灰、不可点），直到**下次重新打开帮助**才复位
```

为什么连点三次：这是唯一一个会抹掉登录态的动作，而它就挨着「知道了」。三次带抖动的点击既是最轻的确认，也足够让手滑的人停下来。

**数据安全**方面做了三件事：
- 退出只删 `session.bin`（DPAPI 密文），账号密码从来没进过本应用，没有别的凭据要清；
- 退出后立刻 `refreshMeta` / 清掉「泳装分享」这类登录专属分类的筛选，否则界面上会留下一个看不见的条件；
- 已下载的图片与索引**不动** —— 那是用户的图库，不是登录凭据。

### 2. 登录引导重排（标注 2/3/4/6）

- 标题行改成「登陆状态」；未登录时只显示「未登录」（去掉后缀说明）；
- 中间那排「保存并验证 / 重新验证 / 清除」整排删掉，「清除」由上面的「退出登录?」接管；
- 底部变成两个按钮：**保存并验证**（已登录时显示为「重新验证」）与**去浏览器登录**；
- 两个按钮都有 **1s 冷却**：点下去立即变灰不可点，1s 后恢复；
- 打开引导时清空输入与提示（上一次的红字不带进来）；失败时给红字，成功时给一条**非红色**的提示条（`.setup-ok`）。

### 3. 红字提示挪到帮助界面（标注 5/7）

拆成两层，各归其位：

- **会话级提示**（`cookie 已过期，请重新登录`、`已清除本地登录凭据`）显示在**帮助**弹窗里，按钮上方；帮助一关就清掉，下次打开不再显示 —— 正好对应「关闭窗口再打开时不再显示」；
- **引导内的操作反馈**（保存成功、保存失败的具体原因）留在引导里，同样是每次打开都重置。

这么拆的理由：#5 要求改的正是那句会话级文案，而 #7 要求它别赖在引导里；但保存失败这类反馈必须留在用户操作的地方，否则点了按钮没有任何回应。

### 4. 顺手补上可靠的自检隔离（这一次踩到的坑）

自检需要一份「未登录」的应用状态，之前用的是命令行 `--user-data-dir`。实测这个开关在**以目录为应用入口**（`electron .`）时并不可靠：Chromium 的缓存目录挪走了，但主进程 `app.getPath('userData')` 还是老地方 —— 结果那次试验真的把用户存在应用里的 session.bin 清掉了。已重新写入同一份 cookie（数据没丢），但教训得记下来。

现在主进程支持 `GUGU_USER_DATA` 环境变量（在 app ready 之前 `app.setPath('userData', ...)`），uicheck 也改用这个变量，隔离是确定的：真机验证隔离实例读到的是「未登录」，而用户真实的 session.bin 毫发无损。

## 遗留

- 「点退出登录?」这条路径**只有代码保证、没有实测**。等用户有空时点一次即可确认（此时凭据会真的被清掉，需要重新贴 cookie）。
- 「去浏览器登录」的 1s 冷却没有自动断言（跑它会把浏览器弹出来），实现上与保存按钮共用同一段冷却逻辑。
- 抖动动画用的是 CSS keyframes + key 重挂载；如果用户觉得幅度或时长不合适，调 `loginJitter` 与 `.jitter` 即可。
