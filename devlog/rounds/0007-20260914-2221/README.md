## 背景

标注工具用了几轮之后，用户对它的**交互形态**提出了重构要求，同时对动效节奏
和沉浸模式的表现提了 4 条具体意见。

## 改动

### 一、标注工具栏重构（用户当面反馈）

**1. 去掉自动收起与呼出把手**

上一轮做的「鼠标离开 5s 后上收 + 靠近顶部呼出」被否掉了。
这次改成**完全由用户掌控**：工具栏常驻，不再自己动。

**2. 工具栏可拖动**

按住空白处即可拖到任意位置，位置跨次打开保持。
两个细节：

- 按钮上不触发拖动，否则按钮点不动
- **纵向刻意不放进窗口拖动区**（自绘标题栏那条，y < 60）。
  上一轮就是栽在这里 —— 工具栏落进拖动区后，真实鼠标点击会被窗口吞掉，
  表现为「左半边能点、右半边不能点」。与其赌 Chromium 会不会把覆盖层
  从拖动区里挖出来，不如直接禁掉这个区域。

**3. 简易工具栏**

- 默认仍是标准工具栏，右侧多了个「收起」按钮
- 简易工具栏只有 4 个图标、无文字：**浏览 / 点选 / 框选 / 展开**
- 浏览的图标是一只手只伸出食指
- 两侧各有一个切换按钮，形态跨次保持

> 需求原文写「4 个图标」，但列举的功能是「浏览 / 切换点选框选 / 展开」三项。
> 这里按 4 个图标实现 —— 把「切换点选/框选」拆成两个独立按钮，
> 功能上完全覆盖，也不会让用户猜一个循环切换按钮当前处于哪一档。

### 二、动效调整（标注 1）

上一轮的重排过渡是 0.16s 且暗态只有 40ms，反馈是**太快了**。
改成：变暗 0.6s + 变亮 0.6s，全程线性，
透明度低于 30% 的区间合计约 0.36s（要求 ≤ 0.6s）。

### 三、沉浸模式（标注 2/3）

**出口按钮**：去掉文字只留图标，背景透明（不再是一块深色按钮遮住画面），
图标从 14px 放大到 18px。

**右下角标题条**：这是本轮最绕的一处，做成了四态机

```
hidden ──切图──> in(0.6s 从右滑入) ──> hold(2s) ──> out(0.6s 下滑淡出) ──> hidden
```

规则按反馈逐条落实：

| 场景 | 行为 |
| --- | --- |
| 完全淡出后切图 | 从右到左滑入 |
| 保持的 2s 内切图 | 立刻换文字，并**重置** 2s |
| 淡出动画中切图 | 重新从右滑入 |
| 退出沉浸模式 | 立刻 0.6s 淡出 |
| 沉浸模式下进入灯箱 | **不**淡入，只有切图才播 |
| 外观 | 只有 4px 白色下边框，背景与其余边框透明，文字 22px |

实现上把「相位」和「文字」拆成两个 state：相位推进只依赖 `capPhase`，
换文字不打断正在进行的动画；要保持期重置计时则借一个 `capNonce` 强制重跑。

### 四、卡片进场淡入（标注 4）

滚到可见高度超过 20% 时淡入 0.4s；**已播放过的永不再隐藏**。

三条约束：

1. 只有「界面之外」的卡片会被先藏起来 —— 首屏可见的不隐藏，否则会闪一下
2. 只在换一批结果（切分类 / 改筛选 / 搜索）时重置：
   给网格加 `key`，整体重挂载。改窗口大小、开合侧栏引发的重排不会重置
3. **性能**：单个 `IntersectionObserver` + 在回调里直接改 DOM class，
   不走 React 状态。上万张图时逐张 `setState` 会把主线程拖垮；
   现在交叉回调不触发任何重渲染

另外给超高长图留了兜底：比例判据之外再加一条「可见高度 ≥ 视口 20%」，
否则比视口高好几倍的长图永远达不到 20% 的比例。

## 遗留

- **NSIS 安装包没打出来**：`electron-builder` 解压 `winCodeSign` 时要创建符号链接，
  普通权限下会报 `Cannot create symbolic link`。免安装目录已经完整可用，
  想要安装包需要以管理员身份运行，或打开「开发人员模式」后重试
- 简易工具栏没有导出入口，标完要切回标准工具栏才能导出
  （按需求原文就是这样设计的，如果嫌绕可以给它加个导出图标）
- 标题条的「向下滑出」是位移 + 淡出同时进行，严格说不是先滑完再消失
- 卡片进场动画在用户把窗口拖得很窄、单列布局时，长图会更容易触发兜底判据
