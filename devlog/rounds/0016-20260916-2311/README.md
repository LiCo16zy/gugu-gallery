## 改动

### 审查结论：暂停确实没生效（三处缺陷）

| # | 缺陷 | 根因 |
| --- | --- | --- |
| P1 | 点「暂停」后阶段不变、按钮不变、看不到任何反馈 | `Engine::pause()` 只置标志 + 写日志，**从不把 `phase` 设成 `'paused'`、也不发事件**；而界面按钮判断的是 `progress.phase === 'paused'` —— 于是永远显示「暂停」、永远再调一次 `pause()` |
| P2 | 单张「下载此图」时暂停完全无效 | `run_ids()`（单张下载）的循环里没有暂停闸门，只有 `download_phase` 与 `index_target` 有 |
| P3 | 运行日志重复刷同一行 | `emit(true)` 每次都把**整个**日志缓冲（≤400 条）发出去，渲染层 `[...prev, ...newLogs]` 直接追加 → 同一行堆 3 遍、"最近 163 条" |

### 修复

- `RunState` 增 `paused / phase_before_pause`；`pause()` 记住当前阶段 → `phase = "paused"` → 发事件；
  `resume()` 清标志 → 还原阶段 → 发事件。`progress_json` 增 `paused` 字段，界面按钮改用 `progress.paused`。
- `run_ids()` 补上与批量下载一致的暂停闸门（300 ms 轮询，暂停中仍可「停止」）。
- 日志行带递增 `seq`，`emit(true)` 只发「上次之后新增」的部分；渲染层在 `jobId` 变化时清空面板。
- 顺带：文件名片段里的空格归一成 `-`（站点标签会带空格，例如「画作 Pid=118581347」）。

**暂停语义（明确写下来）**：正在跑的那**一次请求会跑完**（否则会留半截文件），之后不再取新任务；
继续时从原队列接着跑，**已经下完的不会重来**。
一次任务内的下载队列是任务开始时的快照；跨重启的续爬靠索引侧 `page_marks`（界面「跳过已爬过的页」）
与下载侧「只列缺失文件」——所以「断点继续」是成立的：暂停 → 继续 = 接着原队列跑；
重开任务 = 只补缺失的那些。

### 新增自检

`scripts/check-pause.mjs`（`npm run pausecheck`）：挑图库里最小的 6 个「还没下载」的条目发起批量下载，
点面板上的「暂停 / 继续 / 停止」按钮，断言 13 项（含暂停后进度冻结、按钮变「继续」、阶段「已暂停」、
继续后阶段还原并前进、停止收尾、日志各出现一次）。

## 附：本轮追加的两处（用户口头反馈）

### 沉浸模式切图后标题条显示上一张的信息

**根因**：标题条文案取的是 `detail?.title`，而 `detail` 是新图**异步**加载的；按 ←/→ 时 effect 先跑，
拿到的是上一张的 detail → 先把旧标题写进标题条；等新 detail 回来时，effect 因为
`lastCapId.current === id` 提前 return，**再也不会纠正** —— 于是整段动画都是旧信息。

**修复**：标题条文案改用同步就绪的 `items` 里的标题（`summaryTitle`），并补一个 effect：
详情加载回来且 `detail.id === id` 时再升级成完整标题（只认当前这张）。

**回归锁**：uicheck 新增两条断言 ——「切图后标题条显示的是新图标题」「标题条不是上一张的标题」。
把修复完整回退后这两条确实**失败**（已实测），恢复后通过。
