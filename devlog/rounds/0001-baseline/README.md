## 做了什么

### 一、站点逆向（决定了整个爬虫的形态）

实测 guguxz.com 后确认的几条关键事实，完整笔记见 [`docs/site-analysis.md`](../../../docs/site-analysis.md)：

| 发现 | 对实现的影响 |
| --- | --- |
| 图片接口 `/index/imageBed` 必须带 `Referer`，否则 403 | 所有请求统一注入 Referer |
| `item=<base64>` 给的是**压缩预览图**，`item=<明文路径>&dw=true` 才是**真原图**（1.69MB vs 322KB，差约 5 倍） | 下载统一走 dw 通道 |
| 列表页的 HTML 注释里藏着原图相对路径 | **不必访问详情页就能下载**，请求量减半 |
| 扩展名完全不可信（`.png` 经常实际是 JPEG） | 一律靠魔数判断真实格式 |
| **约 25% 的请求会被截断或挂死**，且截断时 HTTP 状态码仍是 200 | 「重试 + 完整性校验」成为核心机制而非可选项 |

失败形态实测（顺序请求 12 个列表页，间隔 1s）：

```
page=3  FAIL      0 bytes 20.02s   ← 连接挂死
page=6  FAIL      0 bytes 20.02s
page=7  FAIL    618 bytes 20.02s   ← 响应截断，但状态码 200
```

### 二、爬虫

- **两阶段流水线**：先建索引（只抓列表页，极省流量）→ 再按条件下载原图。
  这样你可以「先看一眼有什么，再决定下什么」。
- **完整性校验**：HTML 必须以 `</html>` 收尾；图片实际字节数必须等于 `Content-Length`。
- **指数退避重试**（默认 4 次）+ 请求节流 + 并发闸门 + 下载停滞看门狗。
- **详情页补全**：Pixiv 作品 ID、画师主页、完整标签（可开关）。
- 断点续爬（`page_marks` 表）、暂停 / 继续 / 取消、实时进度与日志。
- 下载落 `.part` 再原子改名，中断不会留下半个文件。
- 附赠**无界面 CLI 模式**，可放进计划任务。

### 三、数据层（本轮由我设计，等审阅）

图库目录自包含，脱离本应用也能直接翻图：

```
<图库根目录>/
├── index.db                 SQLite 索引
├── originals/<一级>/<二级>/  原图（按站点分类归档）
├── thumbs/<id>.jpg          缩略图
└── .tmp/                    下载中转
```

六张表：`items`（站点条目元数据）、`tags`/`item_tags`、`files`（本地文件）、
`sources`（抓取源）、`jobs`（任务留痕）、`page_marks`（断点续爬）。

两个设计取舍：

1. **`items` 与 `files` 分开** —— 「只索引没下载」和「下载了但元数据缺失」两种状态都能自然表达。
2. **分页用 LIMIT/OFFSET 而非 keyset** —— 几万条量级下 SQLite 走覆盖索引扫偏移非常快，
   复杂度低得多；真到百万级再换。

技术选型上的一个被动决定：**本机没有 MSVC 工具链，任何原生模块都装不上**，
所以 SQLite 用了 WebAssembly 版（sql.js）。代价是整库常驻内存、写盘靠整库导出（1.5s 防抖）；
换来的是 `npm install` 之后零编译直接能跑。

### 四、前端

Electron + React + TypeScript，**零 UI 库**，纯手写 CSS 设计系统。

- 左侧资料库导航（全部 / 收藏 / 已下载 / 待下载 / 分类树 / 热门标签）
- 瀑布流网格，滚动到底自动翻页
- 灯箱查看器：缩放拖拽、键盘翻页、缩略图条、元数据面板
- 抓取面板：目标多选、范围与过滤、并发限速、实时进度与日志流
- 设置面板：图库位置、下载行为、网络限速、主题与主题色

## 验证

| 项目 | 手段 | 结果 |
| --- | --- | --- |
| HTML 解析 | `npm test`，用真实抓下的 HTML 当样本 | 23 / 23 通过 |
| 界面交互 | `npm run uicheck`，程序化点一遍关键路径 | 17 / 17 通过，运行期零控制台错误 |
| 真实抓取 | `npm run e2e`，真连站点索引 + 下载 | 240 条索引 / 34 张原图（193MB）/ **0 失败** |
| 渲染正确性 | `npm run shot` + DOM 体检 + 像素直方图 | 无破图、无横向溢出、非空白页 |
| 打包产物 | `electron-builder --dir` 后启动产物 | 正常运行，索引库正常打开 |

自查中发现并修掉的三个真实缺陷：

1. 卡片标题直接用了站点原始文案（`2160x3456 1.69MB [匿名-分享]`），毫无辨识度 → 改用标签作主标题
2. 侧栏分类树的二级项会把别的分类的词也列出来 → 改成一次查询返回完整的「一级 → 二级」树
3. `pageSize` 与 `proxy` 两个设置项只存不用 → `pageSize` 接通；`proxy` 接上 Chromium 网络栈（`net.fetch`）
